## Structure

- `common/hyprland.lua` loads `common/lua/` modules.
- `active/hyprland.lua` and `active/lua` are symlinks to those sources; `active/` is a generated, host-local directory.
- `active/UserConfigs/monitors.lua` and optional `workspaces.lua` are host-specific overrides; do not copy them blindly into presets.
- Original Hyprland `.conf` source files remain only for rollback/reference; `hypridle.conf`, `hyprlock.conf` and non-Hyprland application formats remain valid in their own consumers.
- `stage-lua-recovery.sh` can restore the previous (autogenerated) `hyprland.lua`; it does **not** revert Hyprland binaries.
- `check-hypr-lua.sh` is non-mutating. The legacy `check-hypr.sh` inspects the old `.conf` profile and is not a substitute.

## Finish safely on the existing development branch

Do not switch to `main` while the live entrypoint is linked to this checkout.

```bash
cd ~/projects/scripts/jakoolithyprl
git pull --ff-only
bash -n set-hypr-profile.sh common/scripts/GuardHyprConfig.sh install-lua-guard.sh check-hypr-lua.sh
find common/lua -name '*.lua' -exec luac -p {} +
luac -p common/hyprland.lua
bash ./set-hypr-profile.sh --profile desktop --dry-run
bash ./install-lua-guard.sh --check
bash ./check-hypr-lua.sh
```

**Avoid running the whole `set-hypr-profile.sh` installer against the daily desktop until its generated-tree preservation behavior has been verified.** The new default does not modify PAM faillock; `--configure-faillock` is explicitly opt-in. A full installer invocation can still change other host-local generated paths.

If read-only checks pass, the **focused guard upgrade**, which does not rebuild the profile or use sudo, can be tested:

```bash
bash ./install-lua-guard.sh --install
systemctl --user status hypr-config-guard.path --no-pager
systemctl --user cat hypr-config-guard.path
bash ./check-hypr-lua.sh
```

The guard refuses to overwrite unknown custom `hyprland.lua` files and backs up an autogenerated example before restoring the managed symlink. It is not a rollback mechanism; preserve the previous recovery backup.

## Known incomplete parity / follow-up checks

1. **The two formerly deferred shortcuts now have native Lua implementations:** `Super+Alt+Space` (toggle floating state for every window on the focused workspace) and `Super+Ctrl+O` (per-window opaque override toggle). **Their interactive behavior still requires manual testing.** Zoom wheel also requires manual testing. Do not equate parsed Lua with observed shortcut behavior.
2. Static declarations and `hyprctl configerrors` cannot prove every window rule's effects, device-specific controller configuration, three-finger touchpad gestures, keybind semantic parity, or all shell helper scripts.
3. The machine-specific monitor Lua override was generated from old `eDP-1` and `HDMI-A-1` settings; the active single connected display was reported as `DP-3 2560x1440 scale 1` and falls back to the wildcard monitor rule. Update host-only overrides once its intended layout is confirmed.
4. The corrected wlogout action is in a **local application file**, not yet distributed by this repository; any preset/setup claiming reproducible logout must include a safe handling step.
5. Desktop startup is live-observed; laptop-specific profile behavior and full installer upgrade/restore remain untested.
6. Several legacy shell scripts may still execute old `hyprctl dispatch` or `keyword` syntax; audit before claiming parity.
